# AI Agent 前置地基需求

本目录收录接入 AI Agent 能力前必须补齐的三项基础能力需求。三项均非 AI 专属功能，而是系统自身的架构欠账；不补齐，Agent 无法安全上线。

| 编号 | 文档 | 解决的问题 | 现状结论 |
| --- | --- | --- | --- |
| 01 | [数据权限](01-data-scope.md) | Agent 查询会越权返回全厂数据 | `data.scope.*` 只被 `/api/v1/me` 使用，业务查询零过滤 |
| 02 | [审计日志](02-audit-log-coverage.md) | AI 参与的写操作不可追溯 | 仅 5 个 Service 接入 `sys_operation_logs`，质量/设备/物料/执行链路全空 |
| 03 | [异步队列](03-async-queue.md) | LLM 秒级调用会拖垮接口 | 全仓无 `ShouldQueue`、无 `dispatch()`，且无 worker/scheduler 进程 |

## 为什么必须是这三项

AI Agent 与普通功能的核心差异是**它会代替人发起查询和写操作**。这带来三个硬约束：

1. **查询不能越权**。当前任何持有 `production.reports.index` 的操作员，都能通过接口看到全厂报工。Agent 一旦把列表查询暴露成自然语言入口，越权面会被放大到不可接受。
2. **写操作必须可追溯**。AI 提议、人工确认、系统执行，三步都必须落日志；当前只有订单流转、报工、库存、用户、角色五处有日志。
3. **长耗时调用不能占用请求线程**。LLM 调用通常 5~60 秒，同步执行会占满 PHP-FPM 进程并触发网关超时。

这三项也是 PRD 已声明但未落地的要求：

- `docs/prd.md:1553` —「后端必须校验数据权限」
- `docs/prd.md:1557` —「关键操作记录日志」
- `docs/prd.md:1544` —「支持 Redis Queue」；`docs/prd.md:1561` 第 11.3 节 — 开发环境由 Herd 运行 Queue Worker 与 Scheduler，生产环境由 Docker Compose + PHP-FPM 部署 Queue Worker 与 Scheduler

因此本目录的工作**不是扩张范围，而是补齐既定范围**。

## 三者的依赖关系

```text
01 数据权限 ──┐
              ├──> AI Agent 写操作（人在回路）
02 审计日志 ──┘

03 异步队列 ────> AI Agent 推理与长任务
```

- **01 与 02 共同构成写操作的准入条件**：没有数据权限，Agent 可以对范围外数据发起写操作；没有审计日志，写操作无法定责。
- **03 只服务于 AI 推理链路**：只读查询可以同步完成，不依赖队列。
- 三项之间没有代码依赖，可以并行开发，但**上线顺序建议为 01 → 02 → 03**：01 是安全风险，02 是合规底线，03 是性能与稳定性问题。

## 建议里程碑

| 里程碑 | 内容 | 可验证结果 |
| --- | --- | --- |
| M1 | 01 阶段一：只读过滤 | 跨工厂/产线的列表、详情、看板、追溯均不可见 |
| M2 | 02 全覆盖 | 所有关键写操作产生审计日志，含 AI 标记位 |
| M3 | 01 阶段二：写操作校验 | 跨范围创建/变更被拒绝 |
| M4 | 03 队列可用 | dev/prod 均有 worker 与 scheduler，AI 任务异步执行 |
| M5 | AI Agent 接入 | 只读排查 Agent 上线 |

M5 之前不宜开放任何 Agent 写操作。

## 共同约定

- 模块归属遵循现有 `app/Modules/{Module}/{Controller,Service,Model,Resource,FormRequest}` 结构，不新建顶层目录。
- 新增数据库列必须带简体中文 `->comment()`；外键列把 `->comment()` 放在 `->constrained()` 之前。详见 `.ai/rules/database-migrations.md`。
- 每个需求项都必须有 Feature Test 覆盖，测试放在 `tests/Feature/Api/`，遵循现有 Pest 写法。
- 所有接口变更同步更新 OpenAPI 文档（`app/Core/OpenApi`）。
- 不引入新的 PHP 依赖，除非单独评审。

## 仍需实施前确认

1. **基础数据是否按工厂隔离**。当前产品、物料、BOM、工艺路线、工序均无 `factory_id`。建议保持全局共享，并另立 ADR（01 §4.4、§9.2 Q1）。
2. **`mes_warehouses` 是否新增 `factory_id`**。这是库存按工厂过滤的前提，建议新增（01 §4.10、§9.2 Q2）。
